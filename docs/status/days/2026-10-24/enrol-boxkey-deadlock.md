change: Enrolment step 2 box-key deadlock fix (follow-up to the enrolment deadlock fix, PR 311): the box key write began with a revoke `UPDATE` that matches no row on a sprout's first key and left a gap lock on `idx_pki_sprout_box_keys_one_active`, which every other sprout's INSERT then waited on, so sprouts enrolling in the same second deadlocked (1213) on each other, across tenants too. They were retried, so nothing failed, but the 60-sprout MySQL test counted 39 to 143 deadlocks a run. `upsertSproutBoxKeyActive` now inserts first and takes the revoke-and-upsert path only on a duplicate key (a replay of the same key, or another key active). The fast path is a plain INSERT, not an upsert, since ON DUPLICATE KEY UPDATE on the one-active index would update the other key's row. The same test now counts 0 deadlocks a run, at 60 and at 200 sprouts. A new MySQL test holds one tenant's first box-key and pki_nkeys writes open and checks that another tenant's do not wait on them; on the old code both waited out the lock timeout (1205).
