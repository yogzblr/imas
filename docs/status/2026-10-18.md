- Briefs U1 to U4 written (`docs/briefs/U-hardening.md`) from the owner's decisions: L9, L15, L22, L23, I6 fixed; L24 fixed with a tenant key fingerprint in the join token; cook step events and facts sealed; retention settings configurable in the charts. - Main CI green again after the T batch: T6's `TestSyncNeverRevokesAnotherRowsAcceptedNKey` seeded three rows of one tenant with the same NKey, which T4 (I7, unique `(tenant_id, nkey)`) now refuses, so it failed in setup on main once both merged. The test now asserts the store refuses those rows (`errNKeyAmbiguous`) and still checks the sync; the sync's own guard (`revokeUnlessAccepted`) has a unit test of its own. Test, comment and doc change only; no behaviour change.
- U1 (P3, P4): L9, L15, L22, L23 and I6 fixed with tests. L9: farmer sends `internal.sprout.action`'s `cmd.run` with `no_output`, the sprout leaves stdout and stderr out of its sealed reply, and `controlplane.CmdRunResult` carries the exit code and duration only, so output size no longer matters on that subject. L15: the bus fence counts only routed peers whose server name is one of its own routes' first labels (route hosts must be DNS names; farmerbus refuses IP routes), and fences while any routed peer reports a different route count (`VARZ`); a resize changes every node in one rollout (`deploy/helm/nats` README, "Resizing the cluster"). L22: the sever boundary is in the current tenant-key version's data (`sever_floor`) and the secret's KV `custom_metadata` (`imas_sever_floor`; farmer's `imas-farmer-tenantbox` policy gains `update` on `<kvPath>/tenants/+` metadata), and a gap in the version chain stops the continuity walk. L23: a continuity proof must be inside the ±5 minute window and pass the sprout's persisted replay guard. I6: farmer migration 00007 (`pki_cli_admin_keys`) records the CLI admin keys granted on the Account; one removed from the config (`users.admin` or `pubkeys.admin`) and no user at all is put on the tenant's revoked list, its CLI box keys retired, and the Account re-signed. Ready for security review. (PR #280)
- U2 (P3, P4): L24 fixed with tests. A join token is now `{key_id}.{secret}.{tenant_key_fingerprint}` (`internal/jointoken`; the fingerprint is the lowercase hex SHA-256 of the tenant box public key). saasapi reads the key from farmer over a new sealed request-reply subject, `internal.tenant.boxkey` (`a2f.tenant.boxkey`/`f2a.tenant.boxkey`, added to the SaaS API User's publish list), and mints no key without farmer's sealed answer (`503 farmer_unavailable`, `409 tenant_deprovisioned`); the response also carries `tenant_key_fingerprint`. The sprout checks the tenant key its first enrollment response names against the fingerprint before sealing its proof to it or pinning it (`ErrTenantKeyFingerprintMismatch`, not retried), and refuses a token without one unless `enrollpinrequired: false` (default true; the `imas_sprout_enroll_pin_required` role variable and `packaging/etc/imas-sprout.conf` match), which then warns at every enrollment. Farmer refuses a token whose fingerprint isn't the tenant's current key before redeeming it. Rotation is unaffected (a token is for a first enrollment; continuity proofs carry later keys). The loadtest, the UAT fake stack, harness and K1/K2, `uat/enroll`, the Molecule stub farmer and scenario and the self-update e2e mint or read the new token. Ready for security review. (PR #282)
- U3 (P6): cook step events and facts sealed. Sprouts seal facts (`s2f.facts`) and every step event (`s2f.cook.step`); farmer refuses both in plaintext from every sprout, opens them under the sprout's box keys, checks tenant, sprout, job and the ±5 minute window, and drops replays (facts per replica; step events also once cluster-wide in Valkey, failing closed). Forged, stale, wrong-sprout, wrong-tenant, replayed and plaintext facts change no stored fact, and a forged fact moves no sprout into a cohort; a forged "step succeeded" or a skipped step never makes a job read as succeeded. The CLI and `imas serve` no longer read `imas.cook.*`: they get events from farmer over the sealed `jobs.follow` leg (`f2c.cook.step`, sealed to the user's CLI box key, bound to the request and stream). A sprout on an older build is marked "needs upgrade" (`upgrade_required` in `sprouts.list`/`sprouts.get`, Valkey `imas:upgrade:`, in the tenant erasure inventory). Cost per 3 KiB facts report: +1.3 KiB sealed, 0.19 ms to seal, 0.41 ms to open; no compression needed. Ready for security review. (PR #281)
- U4 (P25, P3): every setting that decides how long data is kept is a chart value, documented in `docs/retention.md` (what, where, default, setting). New: `farmer.retention.jobLogTTL` (`IMAS_JOB_LOG_TTL`, 720h; a bad value used to turn the job reaper off silently and now stops farmer), `farmer.retention.recipeAuditDays` (`IMAS_RECIPE_AUDIT_RETENTION_DAYS`, 365, 0 for ever; farmer's daily sweep of `tenants/<id>/recipe-audit/<day>/`), `farmer.retention.boxKeyGrace` (`IMAS_BOX_KEY_GRACE_DURATION`, 24h), `saasapi.retention.terminalRows` (`SAASAPI_TERMINAL_ROW_RETENTION`, 90 days: the outbox sweeper deletes finished action batches and items, finished provisioning jobs of tenants that are not offboarded or purged, and expired enrollment keys, 500 rows per statement, paced), and Fluent Bit log shipping (`logShipping`, off by default) with a daily retention CronJob (`farmer log-retention`, 30 days, its own list-and-delete credential; not a lifecycle rule, which Versity Gateway v1.8.0 does not implement). A re-mint now deletes the sprout JWT object it superseded. The tenant purge delay is unchanged. Ready for security review. (PR #283)
